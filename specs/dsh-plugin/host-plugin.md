# 宿主侧插件

宿主侧运行在 DSH 的 Node 进程里，由 `cordis.patch.yml` 加载。

## 形状

```js
export const inject = ['webServer']   // 可选：声明你要从 ctx 读取的服务

export function apply(ctx) {
  ctx.effect(() => {
    const timer = setInterval(poll, 1000)
    return () => clearInterval(timer)
  })
}
```

- `apply` 是唯一必须的导出。命名导出即可，不需要 `default` 导出。
- `inject` 声明插件读取的服务。声明后依赖会出现在插件图里；想保持可选，就用 `ctx.get('名字')` 延迟读取。
- 任何可能比“禁用/重载”活得更久的东西——定时器、套接字、监听器、文件监视——都必须以清理函数的形式从 `ctx.effect` 返回，或者通过 `ctx.on` 注册。模块级状态就是泄漏：插件可能在同一个进程里被再次 apply。

## 配置

`cordis.patch.yml` 里那一行的 `id` 是宿主持久化配置时使用的键，必须跨版本稳定；改了它会静默丢掉用户已有配置。配置从这一行读，不要让插件自己另写一个配置文件。

会开端口、起进程、或往自有数据目录之外写文件的行为，默认必须是关闭的。插件被禁用时，对外应表现为“不存在”。

## 错误处理

- 可选依赖失败应当让某个功能降级，而不是让整次 `apply` 失败。
- 定时器、请求处理器里的异常必须捕获并记录；未处理的 rejection 可能带崩宿主进程。
- 不要吞掉“让插件看似什么都没做”的错误——至少要带上能定位是哪一行插件的上下文再记录。

## 落盘

写进 DSH 数据根目录下插件自己的目录，绝不写进仓库。用原子写入（先写 `*.tmp` 再改名），这样崩溃不会留下半截数据；同时把该临时文件模式加进 `.gitignore`。
